# Research output

One file per area **per run**, written by the scout agent, named `YYYY-MM-DD-<area-slug>.md`. A
cycle normally runs an area once, but **an area reported as too large is run again with a higher
cap** (`../docs/briefs/TEMPLATE-area-research.md`), so a cycle can hold several files for one area.
If two runs of one area fall on one day, suffix the slug `-2`, `-3`.

Research output goes here and **never into a conversation** — that is what keeps the cadence
affordable. **What the scout returns instead is the four sections listed in
`../docs/briefs/TEMPLATE-area-research.md`**, and the records stay in the file.

**One scout has run**, on 2026-11-07, before any area was approved:
`2026-11-07-machine-learning-systems.md`, 255 lines. **It was a validation run of the brief, not a
cycle's research** — it was what exposed the three brief defects recorded as V18–V20 in
`../docs/VALIDATION-2026-11-07.md`, and the claim verifier caught a real overstatement in its output
(V21). **Its area was not approved by the owner**, because step 4 has not finished, so **the record
is evidence about the brief and not about the area.** `[2026-11-11]` This paragraph said no scout had
run while that file sat in this directory.

`frames/` holds the framing runs, the source register and the consolidated candidate list that step
4 rules on.
