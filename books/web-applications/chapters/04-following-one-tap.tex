\bookchapter{Following One Tap from Start to Finish}{ch:04-following-one-tap}

\begin{chapterintro}

This chapter puts the two sides together. You will follow one tap on a Save button to the server and back, then meet the common combinations of tools real apps are built from.

\end{chapterintro}

\emph{The problem.} I know the two sides now, but not how one tap travels between them.

\emph{The question.} What happens, in order, between tapping Save and seeing ``Saved!''?

\section{The Whole Trip}\label{04-following-one-tap:the-whole-trip}

\codeneed{11}\begin{codeblock}
\begin{Verbatim}[breaklines=false, fontsize=\fontsize{8.8}{8.68}\selectfont, fontfamily=diagrammono, formatcom=\diagramlines]
 FRONT END              BACK END              DATABASE
 (your browser)         (a server)            (the memory)
 ──────────────         ──────────            ────────────
 1 You tap Save
 2 JavaScript builds
   the request
 3 Look up the address
 4 POST /notes ───────► 5 Route to handler,
   + JSON + cookie        check cookie + rules
                        6 Store the note ◄──► saved
 8 Draw "Saved!" ◄───── 7 200 OK + JSON
\end{Verbatim}
\end{codeblock}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\item
  \emph{The tap.} The browser notices the click and runs the button's JavaScript.
\item
  \emph{The request.} JavaScript builds a request: an action (\texttt{POST}, meaning ``create''), an address, and a JSON body. The browser attaches the site's cookie by itself.
\item
  \emph{The address.} Every request goes to a \textbf{URL}\index{url@URL}, such as \texttt{https:}\allowbreak{}\texttt{/}\allowbreak{}\texttt{/}\allowbreak{}\texttt{notes.}\allowbreak{}\texttt{example.}\allowbreak{}\texttt{com/}\allowbreak{}\texttt{notes}. The middle part, \texttt{notes.example.com}, is a \textbf{domain name}\index{domain name}: a human-friendly name for the server. Computers really find each other by numbers called \textbf{IP addresses}\index{ip addresses@IP addresses}, so the browser asks \textbf{DNS}\index{dns@DNS}, the internet's phone book, to turn the name into a number. The \texttt{https} at the front means \textbf{HTTPS}\index{https@HTTPS}: the request travels sealed, so nobody on the way can read it.
\item
  \emph{The journey.} The sealed request hops across the internet to the server.
\item
  \emph{The back end.} The framework matches \texttt{POST\ /notes} to its route and runs the handler, which looks up the cookie to learn who you are and applies the rules.
\item
  \emph{The database.} The handler asks the database to store the note and waits for ``OK''.
\item
  \emph{The response.} The back end sends back a \textbf{status code}\index{status code}, a number that says how it went, plus JSON. Here is that response exactly as it arrives, shown by \texttt{curl\ -i} (the \texttt{-i} means ``include the headers''):

  \codeneed{3}\begin{codeblock}

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{curl} \AttributeTok{{-}i} \AttributeTok{{-}X}\NormalTok{ POST http://localhost:8000/notes }\DataTypeTok{\textbackslash{}}
  \AttributeTok{{-}H} \StringTok{"Content{-}Type: application/json"} \DataTypeTok{\textbackslash{}}
  \AttributeTok{{-}d} \StringTok{\textquotesingle{}\{"text": "Buy milk"\}\textquotesingle{}}
\end{Highlighting}
\end{Shaded}

  \end{codeblock}

  \codeneed{7}\begin{codeblock}
  \begin{Verbatim}[formatcom=\outputstyle]
  HTTP/1.1 200 OK
  date: Sat, 26 Sep 2026 14:31:05 GMT
  server: uvicorn
  content-length: 24
  content-type: application/json

  {"saved":true,"count":1}
  \end{Verbatim}
  \end{codeblock}

  The first line is the status. Then come headers, notes about the message. After the blank line comes the body: the handler's JSON.
\item
  \emph{The drawing.} JavaScript reads the JSON and changes one paragraph. The browser redraws only that part; the page doesn't reload.
\end{enumerate}

The whole trip usually takes a tenth to a third of a second. You feel it as ``instant''.

\begin{callout}{tip}

Status codes come in families. Numbers starting with 2 mean success, with 4 mean ``your request was wrong'' (404 is ``not found''), and with 5 mean ``the server broke''. The first digit tells you which side to blame.

\end{callout}

\section{Try It}\label{04-following-one-tap:try-it}

Catch a real request in the act.

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Open a site with a search box that suggests results as you type, such as an online shop.
\item
  Open the developer tools, click \emph{Network}, and choose the \emph{Fetch/XHR} filter. This hides images and files and shows only requests made by JavaScript. Clear the list with the clear button.
\item
  Type one letter into the search box. Click the new request that appears.
\end{enumerate}

\emph{Expected result:} A request appears as you type, with status \texttt{200}. \emph{Headers} shows its URL and method, \emph{Response} (or \emph{Preview}) shows JSON holding the suggestions, and \emph{Timing} shows how long the server took. Match each piece to the eight steps above.

\section{Summary, Key Terms, and Review Questions}\label{04-following-one-tap:summary-key-terms-and-review-questions}

\subsection*{Summary}\label{04-following-one-tap:summary}

\begin{itemize}
\tightlist
\item
  A tap runs JavaScript, which builds a request and sends it to a URL.
\item
  DNS turns the domain name into an IP address; HTTPS seals the request for the journey.
\item
  The back end routes the request, checks who you are and the rules, and uses the database.
\item
  The response carries a status code and JSON; JavaScript redraws part of the page.
\item
  A stack is one app's choice of front end, back end, and database.
\end{itemize}
