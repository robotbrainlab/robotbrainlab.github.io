# Glossary

| Term | Meaning |
|---|---|
| Access key | A key ID and secret a program uses to sign requests |
| Artifact | A pipeline's built, versioned output, such as an image |
| Automatic rollback | Restoring the previous version when a new one is unhealthy |
| Availability zone | An independent data centre within a region |
| Cloud | Computers and services rented over the internet by use |
| Configuration | Settings that differ between environments |
| Container | A program running with its own isolated files |
| Continuous delivery | Every passing change is ready to release |
| Continuous deployment | Every passing change is released automatically |
| Continuous integration (CI) | Building and testing every change automatically |
| Declarative | Describing the result, not the steps |
| Deployment strategy | How a new version replaces the old one |
| DevOps | Building and running software as one automated job |
| Digest | A `sha256:` fingerprint naming one exact image |
| Dockerfile | The recipe Docker follows to build an image |
| Drift | Real infrastructure differing from its code |
| Environment | One complete place an app runs, with its own settings |
| Environment variable | A named value handed to a process at start |
| Firewall | Rules deciding which traffic may pass |
| Health check | A quick automatic test that an app copy works |
| Identity and access management (IAM) | Decides who may do what in a cloud |
| Image | A read-only package of files and a start command |
| Image scanning | Checking an image for known vulnerabilities |
| Infrastructure | Everything code needs to run for others |
| Infrastructure as a Service (IaaS) | Renting virtual machines, disks, and networks |
| Infrastructure as code (IaC) | Infrastructure described in files a tool builds from |
| Layer | One build step's file changes in an image |
| Least privilege | Giving each identity only the permissions it needs |
| Load balancer | Spreads requests across healthy copies |
| Managed database | A database the provider runs and backs up |
| Object storage | Files stored by name in buckets, used over HTTP |
| Output (Terraform) | A value printed after `apply` |
| Pipeline | Automated stages every change passes through |
| Plan (Terraform) | A preview of the changes Terraform would make |
| Platform as a Service (PaaS) | A service that runs your code or container |
| Policy | A document of allowed actions on resources |
| Port | A number choosing which program receives traffic |
| Production | The environment real users use |
| Provider (Terraform) | A plugin that manages one system |
| Region | A geographic area of a provider's data centres |
| Registry | A server that stores and serves images |
| Resource (Terraform) | One thing a provider manages |
| Role | Permissions taken on with short-lived credentials |
| Rollback | Returning to the previous good version |
| Root user | A cloud account's all-powerful owner login |
| Secret | Private configuration, such as a password |
| Semantic versioning | Versions in the form MAJOR.MINOR.PATCH |
| Serverless | Code run per event, without managing servers |
| Shared responsibility model | Provider secures the platform; you secure your part |
| Staging | A production-like rehearsal environment |
| State (Terraform) | Terraform's record of what it built |
| Tag | A movable version label on an image |
| Variable (Terraform) | An input to a Terraform configuration |
| Virtual machine (VM) | Software imitating a whole computer |
| Virtual private cloud (VPC) | Your private network inside a cloud |
| Volume | Docker-managed storage that outlives containers |
| Workflow | One GitHub Actions pipeline, in a YAML file |
